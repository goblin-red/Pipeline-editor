# Гоблин на GitHub: две базы, установщик, папка релиза — план

Цель: человек скачивает Гоблин с GitHub и за несколько минут ставит его локально (Mac) или на хостинг.
Один код работает и с MySQL/MariaDB, и с SQLite. Установщик спрашивает всё нужное, создаёт таблицы
и админа, записывает настройки. Код до одобрения плана не трогаем.

## Решения хозяина (02.10.2026)

- SQLite разрешён везде: локально установщик предлагает его по умолчанию, в вебе — MySQL/MariaDB.
- Как запускать локально — выбирает админ при установке: встроенный сервер PHP (Homebrew) или XAMPP/MAMP.
- Перенос данных между базами не нужен: новая установка начинается с пустой базы.
- Для GitHub — отдельная папка релиза (дистрибутив): её собирает скрипт, её же заливаем на GitHub,
  из неё хозяин проверяет установщик.
- Гоблин ставится в папку `goblin/` — путь `/goblin/` остаётся зашитым (XAMPP: `http://localhost/goblin/`).

## Что выяснила ревизия (02.10.2026)

- Вся работа с базой — через `lib/core/db.php` (`db()`, `dbAll()`, `dbRun()`, `dbTransaction()`…); SQL живёт в доменах.
- Приёмы MySQL в запросах `lib/`, `bin/`:

  | Приём | Раз | Как будет в SQLite |
  |---|---|---|
  | `NOW()`, `NOW(3)` | 68 | своя функция в SQLite — запросы не меняются |
  | `INTERVAL n DAY` | 26 (10 файлов) | переписать: граница времени из PHP параметром |
  | `DATE()` | 13 | есть в SQLite |
  | `FOR UPDATE` | 12 | убирает переводчик; запись в SQLite и так под одной блокировкой |
  | `TIMESTAMPDIFF` | 10 | своя функция |
  | `<=>` | 7 | переводчик меняет на `IS` |
  | `CURDATE`, `UNIX_TIMESTAMP` | 5 + 4 | свои функции |
  | `GREATEST`/`LEAST`, `IF`, `CONCAT`, `FIELD`, `REGEXP` | 4 + 3 + 2 + 1 + 1 | свои функции |
  | `information_schema`, `SHOW` (админка: размер базы) | 2 + 1 | ветка по драйверу |
  | `ON DUPLICATE KEY`, `GROUP_CONCAT … SEPARATOR`, `JSON_EXTRACT` | по 1 | переписать руками |

- Схема `sql/schema.sql` (794 строки) и 34 миграции — на диалекте MySQL: `AUTO_INCREMENT`, `unsigned`,
  `ENGINE`, `ON UPDATE CURRENT_TIMESTAMP(3)`, проверки `json_valid`.
- `config.php`: путь к php-cli — от XAMPP. Остальные пути относительные.
- Секреты вне `secrets.php`: `md_backend/ru/backend.md` (пропуска Claude для проверок).
- Встроенный сервер PHP уже есть: `bin/router.php` и инструкция `md_backend/homebrew.md`.
- Нужен PHP 8.0+ (`match`, `?->`), берём 8.1+; расширения: pdo_mysql или pdo_sqlite, curl, mbstring, zip.

## Этап 1. Один слой базы для MySQL и SQLite (`lib/core/db.php`) — сделан 02.10.2026

Итог: `lib/core/sqlite.php` (соединение, функции MySQL, переводчик), `db.php` — `driver`, `dbPrepare()`, свои транзакции;
админка — размер и таблицы базы, бэкап SQLite (`VACUUM INTO`). INTERVAL переводит переводчик — запросы в 10 файлах не тронуты.
Проверка слоя на временной SQLite — 30 из 30; MySQL — без изменений в поведении.

- Настройка `driver`: `mysql` (как сейчас) или `sqlite` — файл `data/goblin.sqlite` (папка `data/` закрыта от веба).
- SQLite открывается с WAL, `busy_timeout` 5 с, `foreign_keys = ON`; транзакция — `BEGIN IMMEDIATE`
  (запись по очереди — этим и заменяется `FOR UPDATE`).
- Недостающие функции MySQL регистрируются в SQLite (`sqliteCreateFunction`): `NOW`, `CURDATE`,
  `UNIX_TIMESTAMP`, `TIMESTAMPDIFF`, `IF`, `GREATEST`, `LEAST`, `CONCAT`, `FIELD`, `REGEXP`.
- Синтаксис, которого функцией не сделать, правит переводчик `dbSql()` в одном месте: `<=>` → `IS`,
  `FOR UPDATE` — убрать. Для MySQL он ничего не меняет.
- Руками (≈15 мест): `INTERVAL` → `dbAgo('7 day')` параметром; `ON DUPLICATE KEY` → `dbUpsert()`;
  размер базы в админке — по драйверу.
- Часы — у базы, как сейчас: SQLite берёт местное время системы (`'localtime'`), формат строки тот же
  `Y-m-d H:i:s.mmm`; `dbStamp()` и `dbMoment()` считают через ту же базу.
- Подводные камни — проверить по коду:
  - MySQL сравнивает строки без учёта регистра (`utf8mb4_unicode_ci`), SQLite — с учётом:
    почте, логину и ключам проекта — `COLLATE NOCASE` в схеме SQLite;
  - число затронутых строк: MySQL считает изменённые, SQLite — подошедшие (места, где код смотрит на ответ `dbRun()`).

## Этап 2. Схема и миграции на две базы — сделан 02.10.2026

Итог: `lib/core/schema.php`, `sql/schema.sqlite.sql` (сверка с живой базой: 29 таблиц, 0 расхождений), `sql/catalog.json`
(48 заготовок). Наборы tests/v2 на SQLite и MySQL: API 32, простой путь 229, эталоны 7, «как пишет человек» 31,
движок 151, лента 44, защита схемы 10, аудит 44, шлюз 12 — всё зелёное; на PHP 8.5 — тоже.

- Источник правды — `sql/schema.sql` (MySQL). Схему SQLite `sql/schema.sqlite.sql` собирает команда
  `php bin/server.php schema-sqlite`:
  - `AUTO_INCREMENT` → `INTEGER PRIMARY KEY AUTOINCREMENT`;
  - `unsigned`, `ENGINE`, `COLLATE` — убрать;
  - `KEY` → `CREATE INDEX`;
  - `ON UPDATE CURRENT_TIMESTAMP(3)` → триггер;
  - `CHECK (json_valid(…))` остаётся: в SQLite она есть.
- Проверка сверяет обе схемы: те же таблицы, поля и ключи.
- Новая миграция с расхождением синтаксиса — двумя файлами: `035-x.sql` и `035-x.sqlite.sql`;
  `migrate` берёт нужный по драйверу.
- Установка с нуля — только схема; все миграции сразу помечаются применёнными.

## Этап 3. Установщик — один мастер, два входа — сделан 02.10.2026

Итог: `public/install.php`, `php bin/server.php install` и `serve`; Терминал вместо `bin/goblin` — там утилита агента.

- Веб: `install.php` — шаги на страницах; работает, пока нет `data/installed.lock`, потом отвечает 404.
- Консоль: `php bin/goblin install` — те же вопросы в Терминале (локально удобнее).

Шаги:
1. **Куда ставим**: на этот компьютер или на сайт — от этого зависят подсказки и выбор по умолчанию.
2. **Проверка**:
   - PHP 8.1+ и расширения;
   - права на запись (`data/`, `storage/`, `workspace/`, файлы настроек);
   - путь к php-cli (`PHP_BINARY`).
3. **Локально — как запускать**:
   - встроенный сервер PHP: `php bin/goblin serve` → `http://localhost:8080`;
   - или XAMPP/MAMP: адрес вида `http://localhost/goblin/`.
4. **База**:
   - SQLite — по умолчанию локально;
   - или MySQL/MariaDB: хост, порт, имя, пользователь, пароль, «создать базу, если её нет»;
   - пробное соединение.
5. **Таблицы**: схема по драйверу, `schema_migrations` заполнена.
6. **Админ и сайт**: логин и пароль админки (хеш — в `secrets.php`), язык по умолчанию (ru/en), адрес сайта.
7. **Ключи ИИ — по желанию**: DeepSeek/OpenRouter, голос OpenAI, Jev. Можно пропустить и вписать позже в админке.
8. **Запись**:
   - `config_admin.php` и `secrets.php` (права 0600);
   - `data/installed.lock`;
   - итог: адрес редактора и админки.

- Папка — `goblin/`, путь `/goblin/` зашит (решение хозяина); встроенному серверу и корню сайта он не мешает.
- На хостинге веб-корень — корень Гоблина (как canvas.goblin.red); `.htaccess` открывает наружу только `public/`.

## Этап 4. Папка релиза (дистрибутив для GitHub) — сделан 02.10.2026

Итог: `php bin/server.php release` → `htdocs/goblin-release` (471 файл, 16 МБ); пробы — `htdocs/goblin-local-test`
(Homebrew PHP 8.5, SQLite, :8090) и https://www.goblin.red/goblin/ (PHP 8.3, MySQL 5.7, база сайта).

- Папка рядом с рабочей: `htdocs/goblin-release/`. Рабочий Гоблин не трогается.
  Проверка установщика локально — встроенным сервером на своём порту (`php bin/goblin serve --port 8090`),
  чтобы не мешать рабочему `goblin/` в XAMPP; для проверки через XAMPP — скопировать в `goblin/` на другом Mac.
- Собирает команда `php bin/server.php release`. Она кладёт в папку только нужное, по белому списку:
  `lib/`, `public/` (без `workfiles/`), `views/`, `lang/`, `instructions/`, `sql/`, `bin/`, `config.php`,
  `config.txt`, `VERSION`, `.htaccess`, `md_backend/` (без секретов). Пустые `data/`, `storage/`, `workspace/` —
  с `.htaccess`.
- Не попадают: `secrets.php`, `config_admin.php`, `config_web.php`, `backup/`, `archive/`, `workspace/`,
  `public/workfiles/`, `data/` с файлами, `tests/` (решить), пропуска из `backend.md`.
- Добавляются:
  - `install.php`;
  - `secrets.example.php`;
  - `.gitignore`;
  - `README.md` (что это, требования, установка локально и на хостинг);
  - `LICENSE`.
- После сборки — проверка на утечки: ключи `sk-…`, пароли, cookie, адреса FTP. Нашлось — релиз не собирается.
- GitHub: в папке `git init`, первый коммит, `git push` в репозиторий хозяина — только после его «да».
  Повторная сборка обновляет папку, следующий коммит — новая версия.

## Этап 5. Проверки (только с разрешения)

- `tests/v2` на обеих базах: тот же набор с `GOBLIN_DB_DRIVER=sqlite`.
- Чистая установка из папки релиза — четыре варианта:
  - локально, SQLite + встроенный сервер;
  - локально, MySQL + XAMPP;
  - веб, MySQL;
  - веб, SQLite.
