# Goblin: архитектура бэкенда

Сервер таким, какой он есть в коде. Источники истины: `public/api.php`, `lib/`, `sql/`, `tests/v2/`.
Пути — от корня проекта `/Applications/XAMPP/xamppfiles/htdocs/goblin`, адрес — `http://localhost/goblin/`.

Остальные документы: [карта файлов](structure.md) · [фронтенд](frontend.md) ·
[прогон: как вести и выполнять](progon.md) · [перевод](перевод.md) · [бэкап](backup.md).

## 1. Что такое Goblin

Редактор блок-схем и учёт их исполнения агентами. Два вида данных:

- **схема** — задания и связи: проект → папки → элементы;
- **прогон** — одно прохождение схемы: попытки шагов и их результаты.

Стек: PHP без фреймворка, PDO, MariaDB/MySQL или SQLite, Apache (XAMPP) или встроенный сервер PHP. Клиент — ES-модули без сборщика.

База — настройка `driver`: `mysql` (MySQL, MariaDB) или `sqlite` (файл `sqlite_file`, по умолчанию `data/goblin.sqlite`).
Код пишет SQL как для MySQL; для SQLite `dbPrepare()` (`lib/core/db.php`) переводит текст через `sqliteSql()`
(`lib/core/sqlite.php`: `INTERVAL`, `<=>`, `FOR UPDATE`, `IF`, `ON DUPLICATE KEY`, `GROUP_CONCAT … SEPARATOR`),
а функции MySQL (`NOW`, `TIMESTAMPDIFF`, `UNIX_TIMESTAMP`, `GREATEST`, `CONCAT`, `FIELD`, `REGEXP`…) зарегистрированы
в SQLite под теми же именами. Часы — у базы: SQLite — местное время системы. Транзакция SQLite — `BEGIN IMMEDIATE`
(вместо `FOR UPDATE`); открыта ли — `dbInTransaction()`, пробный откат — `dbBegin()` / `dbRollback()`.
Прогон ведёт агент-leader обычными запросами в `api.php` — простой путь (`lib/api/simple.php`, раздел 5).
Утилита `goblin` (`lib/cli/`) ходит в тот же API; она оставлена про запас.

## 2. Путь запроса

```text
public/api.php → lib/boot.php → dispatch() → проверка роли → функция домена → PDO → reply() / ApiError
```

- `lib/boot.php` подключает все серверные модули одним списком. Новый файл в `lib/` не работает, пока не вписан туда.
- Реестр `OPS` в `lib/api/router.php` — одна строка на операцию: имя, метод (`GET`, `POST` или `GET|POST`), функция, роли, режим.
- Чтение — `GET`, команды — `POST` с JSON. Форма `application/x-www-form-urlencoded` тоже читается: так сдаёт простой путь (`done`, `fail`). Загрузка файла — multipart с полями `payload` и `file`.
- Проект — параметр `project`, пропуск — заголовок `X-Goblin-Token`.
- Ответ одной формы: `{ok:true, …данные, warnings?}` или `{ok:false, error, code, code2?, …детали}`.
  - Статусы: 401 `unauthorized`, 403 `scope`, 404 `not_found`, 409 `conflict`, 422 `invalid`.
  - Непредвиденное — 500 `server` и строка с пометкой `[goblin]` в `error_log` Apache.
  - Простой путь отвечает текстом — и ошибки тоже; строка сбоя 500 — на языке проекта.
- Кабинет (`public/account.php`) и админка (`public/admin.php`) — серверные страницы со своими обработчиками, мимо `dispatch()`. Общие действия — перенос папки, удаление проекта, уборка — идут через те же функции домена, что и API.

### Три режима операций

| Режим | Что значит |
|---|---|
| `read` | только чтение; `GET` ничего не меняет |
| `batch` | правки схемы пачкой: одна транзакция, одна ревизия, один ключ повтора |
| `single` | одна команда за запрос; все команды прогона — такие |

`single` сам по себе не даёт ни транзакции, ни защиты от повтора — их даёт `engineCommand()` (раздел 6).

## 3. Роли и пропуска

Вызывающего определяет `lib/access/rights.php`: `caller()` и `callerRole()`. Роль берётся только отсюда.

| Пропуск | Вид | Роль | Что может |
|---|---|---|---|
| прогона | `gbr_…` | `lead` | вести свой прогон: выдавать, принимать, возвращать, решать ромбы |
| шага | `gbs_…` | `worker` | одна попытка: пакет, вехи, заявки, сдать или отказаться |
| агента | `gba_…` | `worker` | долгий, принадлежит агенту: сам находит и берёт свои открытые шаги |
| проекта | `gbl_…` | `human` | всё, что разрешено человеку в проекте; к прогону не привязан |
| администратора | область `admin` | `admin` | любая операция: `roleAllowed()` пропускает `admin` всегда |
| cookie `goblin_session` | область `session` | `human` | вошедший пользователь |
| ничего | — | `guest` | как человек; запись ограничена правами проекта (`guest_write`), дела хозяина — нет |

- Области (`tokens.scope`): `session`, `admin`, `project`, `run`, `step`, `agent`; роль сервер назначает по области.
- Долгий пропуск агента в прогоне `engine = 2` работает только с точными прогоном, шагом и сессией процесса (`run_steps.session`).
- В базе — только хеш секрета. Срок жизни считает SQL (`tokenIssue(…, $ttl)`: `NOW(3) + INTERVAL`). Админка показывает состояние: `live`, `expired`, `revoked`.
- Пропуск прогона, шага и агента без дела `TOKEN_IDLE_DAYS` (7) дней гаснет сам (`tokenFind()`); остановка прогона гасит его пропуска (`runStopDo()`).
- Дела хозяина (`OWNER_OPS`: удалить проект, закрыть запись, пропуска, перенос папки) — `requireOwner()`: владельцу,
  пропуску проекта и в проекте без владельца (ключ — пароль). Гость со ссылкой правит только схему.
- Запись (POST) — только со своих страниц: чужой `Origin` получает отказ (`requireSameOrigin()`); агентам (curl) не мешает.
- Пути на диске (рабочая папка, путь материала) — только своего проекта: `pathMustBeInProject()` (`lib/folders/folders.php`).
- Пропуск шага показывается один раз. Потерянный ответ лечится перевыпуском (`step.take` повторно или `step.reissue`), старый пропуск отзывается.
- Принадлежность проверяют `requireProject()`, `sameProject()`, `runOwn()`, `stepOwn()`, `workerAuthorityFresh()`. worker не принимает свою работу.
- Админка — отдельный вход: cookie `goblin_admin` читает только `adminIn()` (`lib/access/admin.php`). `caller()` её не видит, роли в API она не даёт.

**Вход** — по почте или по имени (`userLogin()`); имя при регистрации должно быть свободным (`userRegister()`).

**Рабочие папки** — одна структура на сервере и у агента в вебе (`folderTreePath()`): `<пользователь>-<id>/<проект>-<id>/<папка>-<id>/…/<схема>-<id>`;
пользователь — владелец проекта, у проекта без учётки — `гости`. Новая папка схемы заводится там (`workDirFor()`),
у заведённых раньше путь прежний; пустые папки пользователя и проекта уходят вместе с последней схемой (`workDirDropIfEmpty()`).

**Гости** — люди без учётки (`lib/projects/guests.php`, решение хозяина 30.09.2026):
- проект гостя — без владельца; его ключи помнит браузер (`localStorage`, `api/sync.js`) и шлёт в «Мои проекты»
  (`project.get` без ключа, `&keys=`) — `guestList()`; вошёл — эти проекты становятся его (`guestAdopt()`);
- `projects.seen_at` (миграция 030) — когда открывали; уборка раз в сутки удаляет проекты гостей, которые не
  открывали и не правили `guest_days` дней (`guestSweep()`; 0 — выключено, так по умолчанию на своём компьютере);
- `guest_ai = false` — гостю отказ в помощнике, конструкторе, голосе и тест-прогоне (`GUEST_AI_OPS`, «войдите»), а Jev
  проекта без владельца идёт без общего ключа (`jevAccess()`). На хостинге: 30 дней и `false`.
- `project.get` отдаёт `me` (кто вошёл) и `agentsRemote` — и со списком проектов: у нового посетителя проекта ещё нет.

- Типы элементов: `block`, `decision`, `gateway`, `arrow`, `group`, `area`, `note`, `table`, `link`. Правила типов — `lib/elements/kinds.php` и зеркало `public/src/core/kinds.js`.
- Исполняются только блок, ромб и шлюз; порядок задают стрелки. Ярлык `link` — тематическая ссылка, в прогоне не участвует.
- Оформление — JSON-поле `style`, правила исполнения — `props`; новые ключи в них миграции не требуют. ТЗ — материал роли `spec`, а не название блока.

## 5. Правила записи схемы

1. Правки схемы — доменными операциями через `runBatch()` (`lib/api/batch.php`): транзакция, `FOR UPDATE` строки проекта, одна ревизия на пачку.
2. `opId` + `opScope` — ключ повтора. Сверяется под замком, раньше `ifRev`: то же тело — прежний результат (`repeat`), другое — конфликт. `ref` ссылается на объект, созданный в этой же пачке.
3. `ifRev` сверяет ревизию проекта, `ifFolderRev` — содержимого папки. После изменения растут `rev`, `content_rev`, пишется журнал; удаление клиент видит через `deletions`.
4. Время пишет сервер (`NOW(3)`). Номера элементов и прогонов выдаёт `lib/core/ids.php`. Не путать `id`, `no` и ярлык прогона `rN`.
5. Форму ответа собирают функции `*Shape()`. Вид `work` без оформления, `full` — с ним.
6. Журнал:
   - `via` — только из `JOURNAL_VIA`; правки помощника пишутся с `via=assistant`, конструктора — `constructor`, с подписью и автором;
   - одиночную команду пишет `journalSingleWrite()` при `reply()`;
   - секреты вычищает `journalCleanSecrets()`.
7. Одно действие — одна функция, какой бы вход её ни звал:
   - перенос папки — `folderTransferDo()` (API и кабинет);
   - `agent.save` с `id` меняет только присланные поля;
   - ветка «да/нет» у стрелки проверяется по итоговому `from`.

### Защита активной схемы

Пока в папке идёт прогон `engine = 2` (`running` или `paused`), `lib/engine/guard.php` запрещает менять **смысл** его схемы:
- элементы, состав, `props`, ТЗ и входы;
- назначенных агентов;
- состав команды и среду папки;
- перенос и удаление папки или проекта.

Область — папка прогона, её потомки и цели шлюзов. Отказ: `conflict`, `code2 = active_run` с номером прогона.

Разрешено: оформление, камера, сортировка, несвязанные папки, результаты шагов и обложка, которую ставит сам прогон. Проект с живым прогоном не удалить: сначала `run.stop` с `now=1`.

### Простой путь leader

`lib/api/simple.php` — тонкий слой над движком для агента в терминале: обычные адреса, ответ **текстом**, без пропусков и JSON. Своих правил прогона нет: он зовёт те же `stepAcceptDo()`, `stepDecideDo()`, `stepPassDo()`, `runLiveGuard()`, что и полный API.

| Адрес | Что делает |
|---|---|
| `scheme&folder=N` | схема одним экраном |
| `begin&folder=N` | предпроверка, один живой прогон в папке, завести прогон и отдать первое дело |
| `task&block=N[&text=1][&who=имя]` | задание worker в файл `service/tasks/r<N>/<блок>.<круг>.txt` (`goTaskFile()`), ответ — «задание по ссылке …», и перевод блока в «работает»; `who` — кто делает (лента времени, `stepWhoSave()`). Невыданный блок — «блок не выдан», 409 |
| `work&block=N` | то же зажигание руками |
| `done[&block=N]&result=…` (GET или POST) | принять работу и получить следующее дело. Адрес `N.K:` в начале ответа выбирает круг (`goAnswerAddress()`); чужой круг — 409, повтор принятого — «повтор», в том числе после закрытия прогона |
| `done&block=N&branch=yes\|no\|да\|нет` | решить ромб; та же ветка ещё раз — «повтор», другая — 409 (`goDecidedAgain()`) |
| `fail&block=N&why=…` (GET или POST) | шаг сорвался |
| `again&block=N` | переделать блок: последняя попытка стирается (`stepResetDo()`), пустые наследники — заодно (`stepErase()`) |
| `invite&run=rN[&reply=…]` | вводная worker для среды папки (`goInvite()`); в solo — 409 |
| `text&run=rN&task=N.K\|scheme\|worker` | текст для worker по ссылке: задание, общая картина, инструкция (`goText()`); только чтение |
| `where[&short=1]`, `wait`, `stop` | где мы · подождать событие · закрыть прогон |

- **Сдача длинного ответа** — POST-формой: `curl --data-urlencode result@-` с heredoc `<<'GOBLIN_RESULT'` или `result@/путь/к/файлу`. Ответ до `STEP_RESULT_BYTES` (65535 байт), иначе отказ 422 до записи. `why` режется до `GO_WHY_CHARS` (480 знаков).
- **Честное слово.** Сказал leader «готово» — принято: прогон идёт с `judge = human`, `done` зовёт `stepAcceptDo()` напрямую.
- **Ромбы решает Jev** по условию и ответу worker (`driver = lead`, `jev = judge`); формулу движок здесь не считает. Jev не уверен — решает leader.
- **Ответ всегда содержит следующее дело** и строки о ромбах, решённых ходом (`goMoveLines()`); конец — «ПРОГОН ПРОЙДЕН…» (`goTally()`). Шлюз отмечается тем же `done&block=N`.
- **leader видит каркас** (`goNextLines()`): номер, адрес, состояние, команда. ТЗ и данные — только в задании по ссылке. Исключения: ромб, который Jev не решил, и один раз при `begin` — описание прогона и «СХЕМА КРАТКО» (`goAbout()`, `goSchemeMap()`).
- **Задание worker** собирает `taskMeaning()` (`lib/engine/package.php`): описание, ТЗ и контекст всех рамок — групп и областей — от внешней к внутренней. Тот же смысл получают пакет полного API (`stepPackage()`) и Jev.

Что лежит в задании, какие файлы вешаются на карточку и как вести прогон — [progon.md](progon.md).

## 6. Движок прогона

Весь код — `lib/engine/`. Главное правило: **правило прогона пишется один раз — на сервере**. Утилита и браузер его не повторяют.

| Понятие | Суть |
|---|---|
| Ход | `engineAdvance()` делает всё, что можно без человека: приёмка проверенной сдачи, вычислимый ромб, выдача готовых блоков, закрытие пройденного прогона. Не больше 50 действий за ход |
| Водитель `driver` | кто просит ход: `lead` (простой путь), `manual` или `utility` (утилита). Правила у всех общие |
| Проверяющий `judge` | кто говорит «принято»: `human` или `formal` (код) |
| Jev `jev` | `off` / `advisor` / `judge`; независим от `judge` |
| Жетон | строка `run_marks`: «по этой стрелке можно идти». Кладётся при приёмке, забирается при выдаче, возвращается при возврате, отмене и провале |
| Версия `version` | растёт при каждом настоящем изменении хода; ею будят ожидающих |
| Жизнь `epoch` | сколько раз прогон сбрасывали целиком (`runEpoch()`) |
| Курсор событий | `lastEvent` / `sinceEvent` по `run_events.id`; от версии отделён |

`engine = 1` — прогоны до движка: доживают на старом учёте (`lib/engine/legacy.php`). Новые — всегда `engine = 2`. Живой `run.reset` переводит старый прогон на `engine = 2`.

### Жизненный цикл прогона

Одна таблица переходов — `RUN_MOVES` в `lib/engine/runs.php`, одна проверка — `runMove()`:

| Команда | Из → в | Иначе |
|---|---|---|
| `run.pause` | `running` → `paused` | 409 |
| `run.resume` | `paused` → `running` | 409 |
| `run.reset` | `running`, `paused` → `running` | закрытый — 409 «начни новый прогон» |
| `run.stop` | `running`, `paused` → `stopped` | закрытый — `ok` + `already`, ничего не меняется |
| `run.finish` | `running`, `paused` → `done` (или `failed`) | закрытый — `ok` + `already`, ничего не меняется |

- **Один живой прогон в папке** — `runLiveGuard()`: зовут `run.start`, `run.resume`, `run.reset` и `begin`, под замком.
- **`run.start`** под замком: предпроверка `folderPrecheck()` (не готово — 409 со списком проблем), затем вход `runStartEntry()`. `from` — только вход схемы, иначе 422 с номером входа. Несколько входов без стартера — 422. Прогон и пропуск не создаются.
- **Живой сброс** — `runResetDo()`, одной транзакцией:
  - по каждому элементу — событие `reset` с наибольшим номером попытки (включая невзятые выдачи и прежние сбросы): адреса `N.K` не повторяются, `stepNextAttempt()` берёт их нижней границей;
  - одно событие сброса уровня прогона → `epoch + 1`;
  - шаги и жетоны удаляются, пропуска гаснут;
  - обложки этого прогона снимаются (`runCoversDrop()`), папка `out/rN` остаётся;
  - прогон снова `running`.
- Пауза, продолжение и остановка пишутся в ленту событий: `pause`, `resume`, `stop` (`meta.asked` — попросили или остановлен).

### Граф и предпроверка

`engineGraph()` (`lib/engine/graph.php`) — одна форма схемы для предпроверки, старта и хода:
- `graphRules()` — правила узла в своём виде: стартер — только значение `1` (`propOn()`, как `folderStarters()`), `join` — только `all` или `any`;
- `graphEntries()` — вход схемы: есть стартер — только он, иначе узлы без прямых входящих стрелок.

`folderPrecheck()` (`lib/engine/precheck.php`) по тому же графу называет проблемы номером элемента:
- у ромба ровно один выход «да» и один «нет» (`precheckExits()`);
- неверный `join`, стартеры, узлы без входа при стартере;
- ТЗ, шлюз без цели, цикл без возвратной стрелки, сборщик веток одного ромба с `join = all`.

`propValue()` (`lib/elements/props.php`) не даст записать другое значение `start` и `join`.

### Замок и повтор команды

- `engineLocked()` — транзакция под `SELECT … FOR UPDATE` строки проекта. Тот же замок берут `runBatch()`, задания ИИ и конструктор. Проект запирается первым, поэтому взаимных блокировок нет. Внутри замка нельзя звать `reply()`, спать и ходить в сеть.
- `engineCommand()` — команда целиком: проект, замок, работа. С `commandId` она выполняется один раз:
  - квитанция пишется в журнал в той же транзакции;
  - повтор с тем же телом — прежний исход, с другим — отказ;
  - секрет повторно не выдаётся: `code2 = replay_secret_unavailable` и подсказка (`run.attach` или `step.reissue`).
- После фиксации `advanceAfter()` делает только детерминированный ход, без сети. Его зовут `run.start`, `run.resume`, `run.update`, `run.reset`, `step.open`, `step.accept`, `step.return`, `step.decide`, `step.pass`, `step.submit`, `step.fail`, `step.reset`.
- Остальные команды хода не делают. Jev в полном API спрашивает явный `run.advance`: пометка под замком → сеть вне замка → сверка отпечатка и запись под замком. Простой путь делает такой ход сам (`goMove()`).

### Картинка и лента времени

Обе операции только читают. Каждая отвечает одним снимком базы: версия, жизнь и данные согласованы.

**`run.paint`** (`lib/engine/paint.php`) — что горит на холсте:

| Поле | Смысл |
|---|---|
| `state`, `version`, `epoch`, `pause`, `now` | прогон в миг снимка |
| `blocks[]` | узел: `kind` (`starter`, `block`, `decision`, `gateway`), `state` последней попытки или `ready`, `attempt` (адрес `N.K`), `round` (принято кругов), `lap` (круг текущей работы), `at`, `result`; у принятого ромба — `branch`; у `returned`/`failed`/`cancelled` — `error`; у `ready` — `wait` (`pause`, `decision`, `pass`, `person`); `cover` — картинка-результат этого прогона |
| `edges[]` | стрелка: `lit` — лежит жетон, `done` — все забраны; `pass` — номер прохода, `passed` — сколько прошло |

**`run.timeline`** (`lib/engine/timeline.php`) — лента одного прогона (`run=ID|rN` или последний прогон `folder=N`):
- `run` — прогон, `lifeFrom` (начало текущей жизни), роли и среда папки;
- `lanes[]` — строки исполнителей: ведущий → worker'ы → Jev → движок;
- `bars[]` — попытки блоков (`work`), решения ромбов (`decision`, с веткой и уверенностью Jev), стартер и шлюз (точки). Ромб и шлюз на входе схемы готовы с `lifeFrom`;
- `waits[]` — где прогон стоял без работы, с причиной: `pause`, `decision`, `pass`, `person`, `lead`;
- `marks[]` — старт, пауза, продолжение, остановка, живой сброс (номер жизни), конец.

**История не следует за нынешней схемой и папкой.**
- **Исполнитель** — факт попытки. Лента и `run.state&full=1` (поле `executor`) читают его одной функцией `stepExecutor()`. Порядок: карточка `agent_id` → имя `who` → `lead_self`, записанный при выдаче (`stepLeadSelf()`: solo или карточки без worker — ведущий сам).
- **Старая попытка без факта** — запасное правило по нынешней папке, с пометкой `guess`.
- **Вид отрезка, ветка ромба и цель шлюза** — из событий шага: `open`, `decide.meta.branch`, `pass.meta.target_folder`, стартер — `accept` с `meta.starter`.
- **Правка имени** у взятого шага пишет событие `who` «исполнитель Анна → Борис».

Как это рисует экран — [frontend.md](frontend.md).

### Проверки сдачи

- `checks/files.php` — при сдаче: результат есть (до 200 знаков одной строкой), файлы существуют и лежат в рабочей папке, образец `answer` по виду (отказ `bad_answer`). «Строгие проверки» проекта превращают часть замечаний в отказ. `step.submit` отказывает ответу длиннее `STEP_RESULT_BYTES`.
- `checks/parser.php` — одна грамматика для арифметики `expr` и условия ромба `cond`, без `eval`. `checks/cond.php` считает условие: пробелы любого вида — обычные (`condSpaces()`), словесные правила `содержит`/`contains`, `начинается`/`starts with`, `кончается`/`ends with`.
- `checks/form.php` — образец: дырки `<число>`, `<слово>`, `<файл>`, `<текст>` и английские — без учёта регистра и пробелов внутри; `{имя}` — значение переменной входа.
- `vars.php` — числа из ответа (`a=3`, «кругов 6»). Размер кадра «2832 × 4240» переменной не считается.
- `judges/formal.php` принимает только после **содержательной** проверки: арифметика или образец с `{переменными}`. Иначе — «не уверен», ждёт человека. Ожидаемые числа видит только leader.
- `judges/human.php` всегда «не уверен» и несёт подсказку формальных проверок.
- `judges/jev.php` сначала зовёт формального; Jev дополняет лишь «нет содержательной проверки». `advisor` только советует.

## 7. Встроенный ИИ и Jev

- `lib/ai/jobs.php` записывает задание и запускает `bin/server.php ai-job ID` отдельным процессом. Задание захватывается атомарно (`UPDATE … WHERE state = 'queued'`): два запуска его не выполнят.
- Фоновое задание говорит на языке того, кто спросил (`aiJobLang()`).
- Ответ модели проходит `aiCompile()` и разрешённый набор операций, применение — через `runBatch()` с журналом `via=assistant`.
- Правила собирает `aiRules()` (`lib/ai/settings.php`) по меткам `rule:*`, удалять их нельзя:
  - `instructions/<язык>/deepseek.md` — общие навыки;
  - `рисование.md` — рисование и ТЗ;
  - `конструктор.md` — метод конструктора; к нему сервер добавляет «Опыт каталога» (`catalogDigest()`).
- «Тест-прогон» (`ai.play`) моделирует прохождение и ничего не выполняет.
- Рассуждения модели и шаги сервера пишутся в `ai_messages.think`.
- Разговор помнит папку, где его начали (`ai_chats.folder_id`). История в редакторе — разговоры открытой папки.
- Чаты переживают удаление проекта (`project_id` → `NULL`) ради учёта расхода.

### Каталог схем и конструктор

Каталог — заготовки `templates` с `in_catalog = 1` по разделам `template_categories`.
- Тело — элементы с `ref`, ТЗ, материалы и настройки папки (`roleScheme`, `runEnv`, `shareScheme`).
- Паспорт схемы: для чего, вход, выход, шаги, сервисы, что настраивается, вопросы, грабли. Паспорт раздела: каркас, вопросы, настройка, грабли.
- `catalog.get` отдаёт разделы и карточки, `&template=key` — паспорт и превью.
- Развёртывание — `templateDeploy()`; `template.apply` отвечает ещё и проблемами предпроверки.
- Перевод — поле `i18n`, подставляет `catalogLocal()`. Из перевода берутся только тексты (название, описание, ТЗ) и свойства `answer`, `cond`, `accept`, `reject` (`catalogBodyLocal()`). Устройство схемы — всегда русское тело.

Конструктор — разговор `ai_chats.kind = constructor`, состояния `questionnaire → building → ready → done`:

| Операция | Что делает |
|---|---|
| `ai.build.get` | сессия, история вопросов, текущая карточка, черновик, задание |
| `ai.build.start` | цель человека → новая сессия и первое задание опроса |
| `ai.build.answer` | ответ на карточку; `build` — «Хватит, собирай»; `retry` — повтор сорванного; текст при `ready` — доработка черновика |
| `ai.build.create` | папка из черновика — одна транзакция под замком проекта; сессия — `done` |

- Задания `questionnaire` и `diagram` выполняет `aiBuildRun()` в фоне. Опрос — одна карточка за раз, до 7 вопросов.
- Сборка:
  - `catalogPick()` подбирает похожие схемы;
  - модель возвращает разницу к основе, её накладывает `templateMerge()`;
  - `templateCheck()` разворачивает черновик на пробу с откатом;
  - есть проблемы — до двух кругов починки. Сбой доработки не теряет готовый черновик.
- Модель — рабочее подключение ИИ (ниже, «Голос и личный доступ»); в проверках её подменяет `$GLOBALS['aiFake']`.
- Админка, «Каталог схем»: разделы (`category.save`), заготовки (`template.update`, `template.fromFolder`, удаление).

**Jev (TypeSafe):**
- клиент `lib/ai/jev/*`: `jevCall()` с общим сроком 5 секунд, вопросы по строкам `accept`/`reject`, отпечаток запроса;
- модель закреплена версией `jev_model` (`jev-1.13.0`);
- советчик `step.jev` (`lib/ai/jev.php`) ничего не меняет;
- при `jev = off` наружу не уходит ни одного запроса.

### Голос и личный доступ к моделям

Помощник и конструктор ходят в рабочее подключение ИИ, сигнальщик прогона — в Jev. Подключение — любой API
в формате OpenAI (chat/completions): `ai_connections` в `config.php` (DeepSeek и OpenRouter с `qwen/qwen3.7-flash`),
свои добавляет админка («Встроенный ИИ — подключения к моделям»); рабочее одно на всех — `ai_connection`.
У подключения название, адрес, модель и `timeout`; ключ — `ai_key_<имя>` в `secrets.php`. Из рабочего `configAi()`
(`lib/core/config.php`) собирает `ai_api_url`, `ai_model`, `ai_timeout`, `ai_api_key` — их и читает весь Гоблин;
прежний ключ `ai_api_key` из `secrets.php` подхватывается как ключ DeepSeek. Ответ идёт потоком (`aiHttp()`,
рассуждение — `reasoning_content` у DeepSeek, `reasoning` у OpenRouter):
ждём первых слов (рассуждение или ответ) не дольше `timeout` секунд (по умолчанию 40) —
перегруженный DeepSeek держит запрос в очереди минутами, присылая только «: keep-alive»; дальше обрыв и
«не начала отвечать». Начала писать — не обрываем (до 10 минут). Голос — по настройке `voice_engine`
(админка → «Голос»): `browser` (по умолчанию) — распознавание и озвучка самого браузера, сервер не участвует;
`openai` — OpenAI через операции ниже. Страница отдаёт выбор в `window.GOBLIN_VOICE` (`lib/web/page.php`).
- Общий доступ — настройки установки (админка «Настройки», `config.php`, `secrets.php`): `ai_*`, `voice_*`, `jev_*`.
- Свой у человека — `users.access` (кабинет, «ИИ»); пустое поле — общее.
- Новому человеку (регистрация и «Люди» в админке) кладётся копия общих голоса и Jev — `aiAccessDefaults()`.
  Смена общих потом его не касается; у старых людей — их прежние личные значения.
- ИИ помощника (`ACCESS_AI`) — свой только со своим ключом: без него или с копией ключа установки (`aiSharedKeys()`)
  человек идёт через рабочее подключение админки и переключается вместе с ним (решение хозяина 01.10.2026).
- `aiAccess()` (`lib/ai/access.php`) отдаёт действующий доступ: в запросе — вошедшего, в фоне — того, кто спросил (`aiAccessUse()`).
- Адрес и ключ — пара (`aiAccessPair()`): общий ключ уходит только на общий адрес. Свой адрес без своего ключа —
  без ключа; при сохранении кабинета свой адрес сбрасывает ключ-копию.
- Свой адрес — только https на внешний сервер (`aiUrlGuard()` перед каждым запросом): `file://`, localhost и
  внутренняя сеть — отказ. Голос и проигрывание — только вошедшим (`LOGIN_AI_OPS`, `lib/projects/guests.php`).
- Jev в прогоне — на доступе владельца проекта, без него — на общем: `jevAccess()`; проект запоминает `requireProject()`.

| Операция | Что делает |
|---|---|
| `voice.session` | временный пропуск OpenAI Realtime на живое распознавание; браузер подключается по WebRTC сам, ключ в браузер не уходит |
| `voice.speak` | озвучка текста, в ответе — mp3 |

Обе — режим `read`, в журнал не пишутся; нужны только движку `openai`.
