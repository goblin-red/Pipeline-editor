# Goblin: архитектура фронтенда

Карта браузерного редактора и правила его изменения.
Источник истины — код: `public/index.php`, `lib/web/page.php`, `views/editor/`, `public/src/`, `public/css/`.

Остальные документы: [бэкенд](backend.md) · [прогон](progon.md) · [карта файлов](structure.md) · [перевод](перевод.md) · [бэкап](backup.md).

## 1. Назначение и граница

Фронтенд выбирает проект и папку, правит и показывает схему, ведёт панели (свойства, агенты,
материалы, прогон, ИИ) и **показывает** прогон: подсветку, журнал, ленту времени.

Фронтенд **не ведёт прогон**: не запускает, не продвигает, не принимает, не решает ромбы. Прогон ведёт
агент-ведущий ([progon.md](progon.md), раздел 2), сервер ставит статусы, браузер их читает и красит.
У человека три ручные команды прогона:

| Кнопка | Где | Запрос | Что делает |
|---|---|---|---|
| «■ Остановить прогон» | вкладка «Прогон» | `run.stop` с `now` | гасит и тест-прогон ИИ, и прогон папки; открытые шаги отменяются. Два нажатия |
| «↺ Сбросить схему для прогона» | вкладка «Прогон» | `run.prepare` с `files` | статусы и картинки прошлых прогонов уходят с холста; `out/rN/` и `in/` не трогаются. Живой прогон — отказ. Два нажатия |
| состояние шага руками | панель блока, секция «Шаг» | `step.state` | любое состояние; жетоны сервер согласует сам; «новый» стирает попытку |

Разрешённые чтения: `run.get`, `run.state`, `run.paint`, `run.log`, `run.timeline` и обычная синхронизация.
Других POST прогона браузер не шлёт; поле `needsAdvance` не исполняет.

## 2. Загрузка страницы

```text
public/index.php → lib/boot.php → lib/web/page.php::renderEditor()
  → views/editor/layout.html + частичные шаблоны → import map → public/src/main.js
```

Сборщика нет: ES-модули подключаются по именам `goblin/...` из import map, версия ресурсов — по времени
изменения файлов в `public/src`, `public/css`, `views/editor`. `?view=1` — режим только чтения.
`main.js` задаёт только порядок старта (API, состояние, плашки, шапка, полоса прогона, подсказки, ИИ,
виды, опрос) — доменной логики в нём нет.

## 3. Слои клиента

```text
public/src/
├── api/     HTTP, hash-адрес, загрузка и опрос изменений
├── core/    состояние, события, виды, типы, настройки
├── canvas/  карточки, стрелки, геометрия, камера, облики
├── edit/    правки схемы и очередь записи
├── left/    левая плашка: проекты, папки, инструменты, архив прогонов
├── panel/   правая панель и её вкладки
├── shell/   шапка, окна, журнал прогона, материалы, подсказки
├── ui/      виды: canvas, list, hierarchy, run, timeline
├── run/     подсветка прогона и окно «Начать прогон»
├── mobile/  мобильный скин
└── main.js  порядок старта
```

Правила сервера в HTML, CSS и `canvas/*` не переносятся. Сетевые вызовы — не в `canvas/*`, DOM — не в `core/state.js`.

## 4. Состояние и события

`core/state.js` — одна модель на всё приложение:

| Поле | Что это |
|---|---|
| `project`, `projects`, `folders`, `folder` | проект, мои проекты, дерево папок, открытая папка |
| `elements`, `links` | элементы холста по `id`; ярлыки — отдельно |
| `agents`, `selection`, `tool` | агенты проекта, выделение, инструмент рисования |
| `run`, `runs`, `steps` | выбранный прогон, архив папки, последняя попытка по номеру элемента |
| `runState`, `paint` | снимки `run.state` и `run.paint` выбранного прогона |
| `variant`, `look`, `iso` | вид работы, скин карточек, объёмный вид |
| `rev`, `dirty`, `viewOnly` | ревизия проекта, есть неотправленные правки, только чтение |

Связь модулей — `on()` / `emit()`. Модуль меняет модель и публикует доменное событие; вызывать чужие
функции отрисовки нельзя. Объекты и коллекции правятся на месте: панели держат на них ссылки.

## 5. API и синхронизация

`api/client.js` — единственный HTTP-клиент: `get`, `quietGet` (без всплывашек), `post`, `batch`, hash
`#p=<проект>&f=<папка>&ui=<вид>&run=<прогон>`.

`api/sync.js`:
- `loadProject()`, `loadFolder()` — проект и папка; ответ прежнего проекта или папки не применяется;
- `loadRuns()`, `loadRun()` — архив и выбранный прогон;
- `startPolling()` — `changes?since=REV` раз в секунду.

**Опрос изменений.** Один запрос за раз. Ответ отбрасывается, если за время ожидания сменили проект или
папку, если ревизия в нём меньше применённой или если в очереди есть неотправленные правки.
Скрытая вкладка не опрашивает. Шаги прогона нового движка (`engine = 2`) берутся только из `run.state`
(`run/paint.js`); дельта `changes` лишь будит перечитывание, если прогон уже закрыт.

**Какой прогон на экране** (`loadRuns()`), по порядку:
1. закреплённый в адресе `&run=` — выбор человека: щелчок в архиве, выбор в шапке ленты, «Остановить», ручное состояние шага;
2. идущий или на паузе;
3. последний, где что-то принято; последний с шагами; последний.

Прогоны до метки папки `style.preparedRun` (её ставят «Сбросить схему» и `begin`) по умолчанию не
показываются. Когда опрос видит новую метку, он в тот же миг гасит старую подсветку, снимает
закрепление `&run=` и перечитывает архив — новый прогон встаёт сразу.

## 6. Редактор схемы

`edit/`: `scene.js` — правки и очередь записи; `pointer.js` — выделение и жесты; `place.js` — как объект
попадает на холст; `drop.js` — куда ляжет перетаскиваемое; `inplace.js` — правка текста на месте;
`clipboard.js`, `history.js` (undo/redo, локальная), `align.js`, `grouping.js`, `rehome.js`, `links.js` (ярлыки),
`volume-controls.js` (ручки X/Y/Z в объёмном виде).

**Очередь правок** (`scene.js`). Правка сразу видна на экране; новые элементы живут с отрицательным `id`.
- Правка помнит проект и папку, где её сделали. Через полсекунды правки одного проекта собираются в
  **пачку** со своими проектом, папкой, ключом `opId` и телом.
- Сбой сети — летит **та же пачка с тем же `opId`**, пауза растёт до 15 с. Сервер повтор не применит дважды.
- Отказ сервера — пачка и правки того же проекта, собранные поверх неё, отбрасываются; `resync` перечитывает папку.
- `dirty` снимается, когда очередь и пачка пусты. Ревизия двигается только без пропуска: иначе опрос
  пропустил бы чужие правки.

Сервер сам проверяет права, ревизии и защиту живого прогона; спрятанная кнопка — не защита.

**Инструмент рисования** (`state.tool`). Двойной щелчок по пустому холсту ставит элемент инструмента
(нет выбора — блок), инструмент остаётся. Одиночный щелчок по пустому месту снимает выбор через 0,3 с
(`toolOff`); щелчок по пустому месту плашки или панели и Esc — тоже (`initToolReset()`).

`beforeunload` отправляет очередь и предупреждает о несохранённом. В `viewOnly` правки не создаются.

## 7. Холст

`canvas/`: `view.js` — DOM, камера, частичная перерисовка; `element.js` — карточки; `arrow.js` — стрелки,
подписи веток, «×N»; `geometry.js`, `routing.js`, `geometry-legacy.js` — маршруты; `projection.js` — объём;
`link.js` — ярлыки; `looks.js` — скины; `palette.js`, `volume.js`, `table.js`.

Обычная правка перерисовывает элемент и его стрелки; полная пересборка — при смене схемы или режима.

## 8. Виды и клавиши

`core/variants.js` подключает один из пяти видов (`ui/*.js`, у каждого `mount()`/`unmount()`):

| Вид | Клавиша | Что это |
|---|---|---|
| `canvas` | 1 | холст |
| `list` | 2 | элементы и ярлыки таблицей |
| `hierarchy` | 3 | уровни вложенности колонками |
| `run` | 4 | подробный прогон и полный журнал (значка в шапке нет — вход из вкладки «Прогон») |
| `timeline` | 5 | лента времени прогона (раздел 12) |

Виды работают на общей модели; `unmount()` снимает свои подписки. Переключение идёт с номером
поколения: после любой гонки активен ровно один вид — последний запрошенный.

**Цифры — один обработчик** (`onDigit()` в `shell/topbar.js`, клавиша по месту — `event.code`):
- на холсте 1–8 — инструменты (`TOOLS` в `core/kinds.js`: блок, ромб, шлюз, группа, область, пометка, таблица, ярлык);
- виды — Alt+1…5 везде; простые 1–5 — только вне холста;
- поля ввода, открытое окно, Shift, Ctrl, ⌘, AltGraph и повтор клавиши не перехватываются;
- в режиме «только просмотр» инструменты не включаются.

## 9. Шапка, плашки, панель

**Шапка** (`shell/topbar.js`, `views/editor/topbar.html`): отмена и возврат, ссылка-задание 🔗, в веб-режиме —
папка схемы с диска (`shell/localdir.js`: Chrome и Edge читают и пишут выбранную папку — файлы прогона у агента видны с неё, материалы человека `putFile()` кладёт в её `in/`, если в проекте снята галочка «Хранить материалы на сервере») | четыре
кружка «кто работает» (`#pulse`) и значок режима `#mode-chip` (глобус — веб, компьютер — локально, `project.agentsRemote`; подсказка при наведении) |
переключатель видов, скин карточек, тема, объёмный вид. Первым слева, над плашкой, — значок входа `#btn-account`:
«Мой кабинет» (подсвечен) или «Войти» в подсказке (`state.me` из `project.get`; на телефоне — в меню «Ещё»). Группы разделены чертой `.topbar-split`. **Поиск** (лупа, ⌘K) — по номеру и названию; окошко `fixed`
и встаёт под лупой (левая группа шапки прокручивается и обрезала бы список). Выбор в поиске и строка
«На что посмотреть» в «Сведениях» сначала открывают холст, потом выделяют и подлетают (`flyTo()`).

**Язык интерфейса** — ключи `t('editor.…')`, `tn()`; в шаблонах `{{t:editor.…}}`. Выбор — «Настройки» →
«Язык», cookie `goblin_lang`. Правила — [перевод.md](перевод.md).

**Левая плашка** (`left/`): проекты, папки, настройки, инструменты, цвета. Скины «Классика» и «Студия» —
вкладками (`classic.css`), остальные — разделами. Разделами плашка отдаётся **архиву прогонов**, когда
справа открыта вкладка «Прогон» или открыт вид «Лента». Значок папки и проекта, где идёт прогон, зелёный
и дышит (`pulse` раз в 3 с).

**Боковые плашки прячутся** ярлычком у края (`shell/sides.js`, выбор помнится в браузере). Щелчок по значку
вкладки спрятанной плашки (`.rail-tab` слева, `#panel-tabs [data-tab]` справа) возвращает её.

**Правая панель** (`panel/tabs.js`), вкладка помнится в `goblin-panel-tab`:
- `props` — свойства (`panel/panel.js`). Секция «Шаг N.K»: состояние, **исполнитель**, время, результат,
  ручное состояние. Исполнителя даёт сервер — `run.state` → `steps[].executor`, тот же ответ, что строка
  ленты; своего правила по нынешней папке у панели нет. `guess` (старая попытка без факта) — «Анна
  (предположение)» и пояснение под строкой. Данные без поля — прежнее правило `executorGuess()`;
- `agents` — «Состав команды», «Среда прогона папки», галочка «Давать worker общую картину схемы»
  (`panel/agents-view.js`; смысл — [progon.md](progon.md), раздел 2);
- `assets` — материалы;
- `run` — «Начать прогон» (окно с двумя ссылками-заданиями агенту — прогон и рисование, `api.taskLink()`, — и пояснением, куда их отдать; запуск делает ведущий), «Остановить», «Сбросить схему»,
  «Лента времени прогона», полоса прогона (`shell/runbar.js`: чего ждёт, шаги, счёт принятых) и краткая лента;
- `ai` — помощник (раздел 13).

## 10. Подсветка прогона

Поля ответов `run.state`, `run.paint` — в [backend.md](backend.md), раздел 6 «Картинка и лента времени».
Здесь — как их рисует экран.

### Одна таблица «состояние → вид»

Все цвета — в `css/run.css`: состояние ставит JS (`data-step` у карточки, `data-state` у строк полосы,
списка, вида «Прогон», ленты), цвет — переменная `--run` из токенов `--step-*` (`tokens.css`, светлая тема —
насыщенней). Кроме цвета у каждого состояния свой значок (`STEP_MARKS`, `stepMark()`) и узор — различается
и без цвета. Цвет карточки, выбранный человеком, остаётся: состояние лежит поверх.

| Состояние | Блок | Значок |
|---|---|---|
| не тронут (прогон выбран) | серая полоса слева | — |
| ждёт команды (`ready`) | розовая пунктирная рамка, редкий зов; пауза показа — рамка точками, спокойно | ✋, у паузы … |
| выдан | синяя полоса, тихое свечение | → |
| в работе | оранжевая полоса и перелив, частое свечение | ◉ |
| сдан | янтарная полоса и заливка; итог проверок — только здесь | ⌛ |
| принят | зелёные косые полосы; круг цикла | ✓, ↻N |
| возвращён | фиолетовая полоса и заливка | ↩ |
| сорван | красная полоса и красные полосы | ✗ |
| отменён | серая пунктирная полоса, содержимое притушено | — |

- **Ромб**: контур цвета состояния; ждёт решения — розовый и «?»; решён — цвета «принят» при любой ветке,
  ветку показывает выделенный ярлык «ДА» или «НЕТ». Красный на холсте — только «сорван».
- **Шлюз** — кольцо цвета состояния; **стартер** пройден — толстое кольцо и ✓ вместо ▶.
- **Схлопнутая группа** — полоса самого срочного состояния внутри.
- **Скин меняет форму знака**, не цвет: полоса слева (рабочий, классика, дизайнер, разработчик, leader —
  7 точек, показ); вся рамка (минимальный, мобильный — `looks.css`); точка у названия и полоса 3 точки (студия).
- **Стрелки** — цвета блоков: бежит (`live`) — оранжевый бегущий пунктир; пройдена (`done`) — зелёная;
  жетон лежит и ждёт (`lit`) — розовые точки; «×N» — сколько раз прошли.
- **Плашка прогона** в углу холста (`.run-chip`, `drawChip()`): в покое — значок и «r12» цветом состояния
  прогона, слово («идёт», «пауза», «остановлен», «дошёл до конца», «сорвался») раскрывается при наведении, как
  у ярлыков. Щелчок прячет плашку до смены прогона или его состояния (`chipHidden`, `chipKey()`); плашка
  в `UI_OVER_CANVAS` (`edit/pointer.js`) — холст её щелчок не забирает.
  В паузе и у закрытого прогона свечение «в работе» и «ждёт» замирает. `prefers-reduced-motion` снимает анимацию.
- **«◎ Следить»** — кнопка рядом с плашкой (`run/follow.js`), видна, пока прогон идёт или на паузе. Нажата —
  холст сам плавно едет (`flyTo`, масштаб человека не трогает) к только что открытому узлу: выдан, в работе,
  сдан, ждёт (`openBlocks()` из `run/paint.js`). Открылось несколько сразу — к меньшему номеру; узел закрылся,
  а новых нет — к любому ещё открытому. Выбор помнит браузер (`runFollow` в `core/settings.js`, тот же
  переключатель — в окне настроек холста). Проверка — `check-paint-ui.mjs`, раздел 10.
- **Стартер мигает только в начале прогона** (очередь показа `run/paint.js`). Чтение инструкции ведущим
  (`docs.run`) стартер больше не зажигает — отметка `lead_seen_at` убрана миграцией 032.
- **Новая папка** (`addFolder()`, `left/folders.js`) создаётся сразу со стартером «Начало» — одной пачкой.
- **Приветствие** (`shell/welcome.js`, окно `#dialog-welcome`): первый заход человека без учётной записи на новый
  пустой холст (`loadProject()` вернул null) — картинка `img/welcome.png`, пара строк и два пути: «Пустой холст»
  (`createFolder()` — первая папка со стартером) или «Готовая схема» (каталог). Один раз на браузер (`goblin-welcome`);
  не показывается вошедшему, по чужой ссылке и в режиме просмотра.
- **Выпуск системы** — файл `VERSION` в корне; подпись под логотипом в настройках (скины с вкладками).
- **Вложенные папки** (`left/folders.js`, список строками): папку тащат на другую — ложится внутрь, на своего же родителя или на «…» — выходит уровнем выше
  (`folder.update` с `parent`, `moveFolder()`); в свою же ветку не бросить. У вложенной папки при наведении — значок
  «на уровень выше» (`.tree-lift`). Стрелка ▸ в значке сворачивает ветку,
  свёрнутые браузер помнит по проекту (`goblin-folders-shut`); ветка открытой папки всегда раскрыта. Вложенность видна
  во всех скинах (`nest()`, класс `nested` и `--depth`): строки — отступ, длинное имя — троеточием,
  уголок «└» от родителя; «Студия» (плитки) — деревом со сдвигом, уголком и стрелкой сворачивания; телефон — сдвиг
  с полосой. «Классика» — уровнями, как в Finder (`drawLevel()`): видны папки одного уровня, щелчок по папке
  с подпапками («›») открывает её и заходит внутрь, сверху — папка уровня, «↑» — уровнем выше, «Новая» — в этот уровень.
  Значок «на уровень выше» — и у вложенных плиток. Под кнопками — примечание «Перетаскивайте папки…» (не на телефоне).
- **Панель папки:** локально рядом с рабочей папкой — «Открыть»: сервер на этом же Mac открывает её в Finder
  (`folder.open`; папки ещё нет — «появится при первом прогоне»). В вебе у «Папки схемы у агента» —
  «Скопировать путь»: полный путь из последнего прогона (`agentDir`), до прогона — относительный.
- **Прежние прогоны** (`engine = 1`) красятся по шагам; решённый ромб мигает 3 с, ветка — по выбранной стрелке.

### Очередь показа — вовремя

`run/paint.js` держит долгий `run.state` (`since`, `wait`, `full`) и при новой версии читает `run.paint`;
пропала картинка — повторяет. Своих правил прогона и своего опроса у экрана нет.

Между сервером и холстом стоит очередь показа (фича наглядности, срок — «Прогон: задержка показа» в
настройках холста, `runShowMs()`, по умолчанию 3 с; выключена — сразу последнее состояние):
- каждое новое состояние держится свой срок и мигает; ни один статус не теряется, последний доходит всегда;
- **волна**: в одной картине переход идёт по схеме — закрылся блок, побежала его стрелка, открылся или
  решился следующий узел; каждый шаг волны на полсрока позже;
- **предел задержки** `lagMax` — 6 с или два срока: отстала очередь — переходы короче (не меньше 0,4 с),
  а просроченное сворачивается до последнего; прошлое не выдаёт себя за живой статус;
- остановка, конец и срыв — сразу, без очереди; новые реквизиты той же стадии (адрес, причина) — на месте;
- **первая картина** — сразу, без мигания: открыли страницу, сменили прогон, вернулись на спрятанную вкладку,
  живой сброс (`epoch` вырос). Прогон, начатый только что, показывается переходами.

Ответ чужого прогона, прежней жизни (`epoch` меньше) или не новее показанного экран не откатывает.

### Результаты и их актуальность

- **Обложка** (`coverAsset()`, `coverUrl()`): картинка-результат прогона, который сейчас на холсте, — поле
  `cover` из `run.paint`; у старого прогона она видна и после «Сбросить схему». Иначе — обложка человека.
  Картинки других прогонов к картине не липнут; скрепка с числом их не считает.
- **Ответ на карточке, секция «Шаг» и лента** — выбранного прогона.
- Где видна обложка: «Классика», «Дизайнер», «Показ», «Студия»; «Рабочий», «Разработчик», «leader» её прячут.

## 11. Журнал, материалы

`shell/runlog.js` — краткая лента (вкладка «Прогон») и полный журнал (вид «Прогон»); вид строки один:
шапка `r137 начат 22.09.2026 11:00:54`, дальше строка на событие — номер, время, значок и номер элемента,
кто, что случилось. Значки — одни на весь редактор (`iconOf()`, `STARTER_ICON` в `core/kinds.js`); слова
«ромб 138», «блок 137» заменяются значками (`iconify()`). Тяжёлое тело события грузится при раскрытии.
Лента перечитывается только при настоящей перемене прогона.

**Архив прогонов** — `runsList()`; щелчок по прогону закрепляет его в адресе.

**Материалы** — `asset.*`. Плитку или строку материала перетаскивают на блок, группу или таблицу —
он прикрепляется ролью `attachment` (`edit/place.js`, `ASSET_DATA`); на выделенном — ко всему выделению.
ТЗ — материал роли `spec`.

## 12. Вид «Лента»

Лента времени одного прогона: строки — исполнители, на шкале видно, **кто какой блок брал и когда**.
Код — `ui/timeline.js`, стили — `css/timeline.css`; данные — `run.timeline` ([backend.md](backend.md), раздел 6).

- **Вид — всегда в палитре и шрифтах «Студии»**, при любом скине и теме; цвета состояний — та же таблица подсветки.
- **Шапка**: плашка прогона, выбор прогона папки (всегда список открытой папки; прогон не выбран — первой строкой «—»),
  время начала, «Весь прогон», «Сейчас». `loadRun()` не открывает прогон чужой папки.
- **Шкала** — минуты и секунды от начала прогона; абсолютное время — в подсказке над шкалой.
- **Строки**: «ожидание» (штриховка с причиной) и исполнители — ведущий, worker'ы, Jev, движок; имена закреплены слева.
  Вся строка — догадка (все её отрезки `guess`) — «≈ имя», курсивом, под именем «предположение».
- **Отрезок** — попытка блока цветом состояния; гуще — работа от «взят» до «сдан»; подпись «▣ 11 Счёт · 11.2 ↻2».
  Ромб — своей формой, с «ДА»/«НЕТ»; мгновенное решение, шлюз, стартер — отметки. Отрезок не уже 8 точек.
- **Параллельная работа одного исполнителя** — уровнями внутри его строки (`levels()`): пересекающиеся
  отрезки встают друг под другом, строка растёт в высоту, каждый виден и кликабелен. Открытый отрезок держит
  уровень до конца ленты. Ширина отметки — замер её подписи («◆ 1234 НЕТ»), на скрытом виде — запас `POINT_W`.
- **Черты** поперёк ленты: старт, пауза, продолжение, остановка, живой сброс, конец; оранжевая — «сейчас».
- **Управление**: масштаб — колесо над шкалой или Ctrl/⌘ и колесо; пока масштаб не трогали, прогон вписан
  целиком. Щелчок — выделить блок и открыть свойства; двойной — на холст к блоку.
- **Подсказка** при наведении — о **той попытке**, над которой курсор: «попытка N.K», круг, исполнитель
  (догадка — «(предположение)» и почему), выдан, взят, сдан, закрыт, длительность, ответ, причина.
  Лента отдаёт ответ укороченным (оканчивается «…») — полный дочитывается из `run.get` один раз на снимок
  (`fullAnswer()`); после ожидания сверяется, что вид открыт, снимок тот же и курсор на том же отрезке.
  Ответ — в своём окошке; щелчок по отрезку **закрепляет** подсказку: она стоит на месте, ответ прокручивается
  целиком; снимает Esc или щелчок по пустому месту ленты. Панель при этом, как и раньше, показывает блок.
- **Живой прогон** обновляется от той же версии, что подсветка; своего опроса нет, открытые отрезки растут по часам.
- **Сбой чтения `run.timeline`**: остаётся последний хороший снимок того же прогона, версия показанной не
  считается; до 6 повторов с растущей паузой (1, 2, 4… до 15 с) — и у закрытого прогона. Смена прогона или
  уход с вида повторы отменяют; ответ прежнего прогона на новый не ложится (`turn`).
- **Мобильный скин**: вид доступен из вкладки «Прогон», шкала листается пальцем, строки уже.

## 13. ИИ-помощник

Вкладка ИИ (`panel/ai.js`) — чаты, охват «Папка | Проект», ссылка на разговор (`chat.php`, `shell/chatpage.js`).
Разметка текста — `ui/rich.js`.

- **Тест-прогон** — пункт быстрого меню: схема проигрывается на выдуманных ответах (`ai.play`), ничего не записав;
  гасится «Остановить» и кнопкой прерывания.
- **Голос** (`panel/voice.js`): микрофон — диктовка по ходу речи в поле, на место каретки; второе нажатие
  сдаёт остаток и ждёт итог; текст **остаётся в поле**, отправляет «Спросить». Правка поля руками главнее.
  Отправка вопроса обрывает и диктовку, и подключение микрофона. Уход с вкладки ИИ выключает микрофон и озвучку.
  Движок — `window.GOBLIN_VOICE` (настройка `voice_engine`): **browser** (по умолчанию, бесплатно) — `SpeechRecognition`
  на языке интерфейса; Chrome замолкает после тишины — слушаем заново, обрыв (сеть, микрофон) гасит кнопку
  (`onDictationLost`); чтение — `speechSynthesis`, язык по буквам ответа, голос Google, кусками до 200 знаков.
  **openai** — WebRTC к OpenAI (`voice.session`), звук ответа — `voice.speak`. В Firefox диктовки браузера нет.
- **Ключевые слова** — значок рации у микрофона (`goblin-ai-words`, по умолчанию включён): на языке интерфейса —
  «Приём» в русской версии, «Roger» в английской — отдельным словом в конце речи убирается из поля, диктовка кончается и вопрос уходит сам (`dictate(field, { onWord })`).
  Браузер — только в законченной фразе, OpenAI — после секунды тишины: «приём у врача» не отправит. Подсказка — под полем.
  **Разговор голосом**: после вопроса, отправленного словом, микрофон гаснет, ответ звучит (если включён динамик;
  `speak(text, { onDone })`), затем микрофон включается сам. Кончается, когда человек выключил микрофон руками,
  выключил значок рации, нажал «Стоп» или ушёл с вкладки.
- **Динамик** — своя опция (`goblin-ai-read`): включён — каждый новый ответ звучит; выключили — звук стихает сразу.

**Окно «Новая схема»** (`shell/newscheme.js`, `#dialog-newscheme`): вкладки «Каталог» (`catalog.get`,
`template.apply`) и «Конструктор» (`ai.build.*`); ответ прежней вкладки или закрытого окна не применяется.

**Подсказки** (`shell/tips.js`) — табличка под значком сразу, без задержки браузера; на карточках холста и
в открытых окнах — нет.

## 14. Детали, на которых спотыкаются

**Путь правки до базы**: мышь или панель → `edit/scene.js` → пачка → сервер отдаёт `id` и ревизию.
Для нового поля мало колонки и HTML: нужны запись, выдача в схеме, в дельте `changes` и потребитель.

**Камера** (`canvas/view.js`) — сдвиг и масштаб по папке в `goblin-camera` (20 последних). Запись — при уходе,
скрытии вкладки и выходе из холста; `activeCameraKey` не пишет чужую. `fit()` — только без сохранённой камеры
или по просьбе. `flyTo()` — плавный перелёт к объекту.

**Объёмный вид** (`goblin-iso`): `canvas/projection.js` — единственный источник матрицы, габаритов и порядка
(`surfaceElement()`, `projectedBounds()`, `depthOrder()`). `style.x/y/z` — основание, `width/height/thick` —
размеры. В `volume-controls.js` перед итоговой правкой вернуть исходные поля, иначе undo запомнит изменённое.

**Первый заход** (в браузере ничего не выбрано): скин и вкладка левой плашки — настройки установки `look_default`, `rail_default` (config.php: «Рабочий» и папки; сайт canvas.goblin.red — «Классика» и «Настройки», config_web.php), страница отдаёт их в `window.GOBLIN_DEFAULTS` (`lib/web/page.php`); на телефоне — всегда мобильный.

**Записка агенту ИИ** (`agentNote()`, `lib/web/page.php`): первая строка HTML холста — комментарий по-английски:
страница для человека; агенту, которому по ошибке дали адрес холста, — ссылки `docs.run` прогона (`role=lead`)
и рисования (`role=draw`), проект и папку он берёт из `#p=…&f=…` адреса (сервер хвоста не видит); неясно —
просит у человека ссылку из кнопки-ссылки шапки. Копия — скрытым `<pre class="agent-note">` в начале `<body>`:
часть агентов читает страницу текстом без комментариев.

**Скины** (`canvas/looks.js`, выбор — `goblin-look`, тема — `goblin-theme`) меняют только CSS. «Студия» —
`studio.css`, всегда тёмная. Мобильный — `mobile/`, `mobile.css`: вертикаль, холст главный, меню вкладками;
из видов — холст и «Лента». «Минимальный» и «Мобильный» прячут бирки ярлыков и значки карточки.

**Стрелки**: алгоритм — `canvas/geometry.js`; подложку подписи меряет `refreshArrowLabelPlates()`.

**Иерархия**: перетаскивание — `edit/rehome.js` (состав и перенос с содержимым); родитель — внутренняя, затем
меньшая рамка (`core/tree.js`); настройки — `goblin-tree`, `goblin-tree-links`.

**Разметка**: кнопка сворачивания группы живёт в `.node-title`; подсветку Markdown и JSON в окнах делает
`paintCode()`; плашки стоят по явным колонкам сетки `.workspace`.

**Стартер** — блок с `props.start`: класс `starter`, круг, номер и имя (до `STARTER_TITLE_MAX`); второй стартер
в папке нельзя; вставка из буфера снимает флажок, если стартер уже есть. Правила — [progon.md](progon.md), раздел 4.

**Ярлыки** — в `state.links`, рисует `canvas/link.js`, правит `edit/links.js` своим запросом. Бирка у края:
у владельца «↗ 57», у цели контурная «↙ 12», входящий шлюз — «⬡ N»; наведение раскрывает «· папка · имя»
(до 20 знаков, `LINK_NAME_MAX`); щелчок — перелёт к цели на 80 %. Ставят инструментом «ярлык» (клавиша 8)
двумя щелчками или протягиванием. Шлюз между папками — тоже бирка (`gateLinks()`), без своей записи в базе.

## 15. Правила изменений

1. Найти владельца логики: api, sync, state, edit, canvas, panel, shell, ui, run.
2. Сетевые вызовы — не в `canvas/*`; DOM — не в `core/state.js`.
3. Все записи — через `api.post` / `api.batch`; права проверяет сервер.
4. После изменения модели — точное доменное событие.
5. Асинхронный ответ — с поколением проекта, папки, вида или рендера.
6. Runtime POST браузера — только три команды человека (раздел 1).
7. Состояние прогона не вычислять из цвета, DOM, таймера или текста ответа — только поля сервера.
8. Цвет состояния — только из `run.css` (`--run`), своих копий не заводить.
9. Изменили формат API — проверить `api/sync.js`, `run/paint.js`, панель и затронутые виды, `viewOnly`.
10. Не брать код из `backup/` и старых документов.
