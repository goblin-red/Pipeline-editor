# Translating Goblin into English

Rules for everyone who translates the interface and documents. The owner's decisions of 29.09.2026:

- the code uses **keys**; the texts live in the dictionaries `lang/ru/*.json` and `lang/en/*.json`;
- **each person picks their own language**: the "Language" switch in the "Settings" menu, remembered in the cookie `goblin_lang`;
- md files and documentation are kept in **a separate `ru/` folder and a separate `en/` folder**, with the same file names;
- texts for agents and the built-in AI (run, AI rules, scheme catalog) use **the project language**
  (`projects.lang`), `agents.*` keys through `ta()`; done in phase two on 29.09. The `goblin` utility
  (`lib/cli/`) is not translated — it is kept in reserve.

## How it works

| Where | How to write it |
|---|---|
| dictionary | `lang/ru/<part>*.json` and `lang/en/<part>*.json` — flat JSON `{"key": "text"}` |
| JS | `import { t, tn } from 'goblin/core/i18n.js';` → `t('editor.panel.folder_name')` |
| HTML view (`views/…`) | `{{t:editor.settings.title}}` — both in text and in attributes (`title`, `placeholder`, `aria-label`) |
| PHP | `t('server.folder.not_found')`, `tn('server.steps', $n)` — `lib/core/i18n.php` |
| substitution | `t('editor.folder.delete_ask', { name })` ↔ `"Удалить папку «{name}»?"` |
| number with a word | `tn('editor.steps', n)` ↔ keys `editor.steps.one/few/many` (ru) and `editor.steps.one/other` (en); `{n}` is the number |

The browser gets the dictionary right inside the page (`langScript(['common', 'editor'])` in `lib/web/page.php`),
before the modules load, so `t()` works at the top level of a module too. If there is no translation, the
Russian text is shown; if there is no Russian text either, the key itself is shown.

A **key** is `part.place.meaning`, in Latin letters, `snake_case`: `editor.panel.folder_name`,
`admin.users.delete_ask`, `server.element.no_title`. The part is the first word of the key and the start of the
dictionary file name: `editor.*` keys live only in `lang/*/editor*.json` (you can split them: `editor-panel.json`).
`common.*` holds shared words (Close, Cancel, Done…) — read only, do not add new ones.

## Rules

1. **The Russian text in the dictionary stays exactly as it was**, letter for letter, with "guillemet" quotes «like this» and the ellipsis.
   The Russian interface must not change by a single character: the checks compare the Russian labels.
2. A key is added **to both dictionaries at once** — ru and en.
3. A phrase is one whole key, with substitutions like `{name}`. Do not build a translation from pieces:
   English word order is different.
4. Numbers with words (step/steps) go through `tn()`, not through home-made functions.
5. **Do not translate:** comments in code; API operation names (`folder.update`), JSON fields, CSS classes,
   element types in data (`block`, `decision`); data from the database (names of projects, folders, blocks;
   the scheme catalog is translated through its own `i18n` field); journal and feed entries already saved to
   the database; the `lib/cli/` utility; `config.txt`.
5a. **Text for agents and the model** (`lib/engine/`, `lib/ai/`, `lib/api/simple.php`, `lib/api/instructions.php`)
   — `ta('agents.…')`/`tna()` in the project language, dictionaries `lang/*/agents*.json`; long texts —
   `instructions/<lang>/*.md`. For a person — `t()` in their language. Parsing agents' replies — in both languages.
6. If a function has its own variable named `t` (time, fraction), rename it before calling the translation function.
7. A server message (`ApiError`) goes through `t('server.…')`: the language comes from the cookie of whoever asked;
   an agent without a cookie gets Russian.
8. Edit only the files of your own part (table below). If you need someone else's file, write it in the report; do not edit it.
9. English is simple and short, like in good interfaces: Sentence case ("Create folder",
   not "Create Folder"), no bureaucratic language.

## Run protocol words

The server prints them (`lang/*/agents.json`, `ta()`), agents and instructions read them (`instructions/*/прогон.md`),
and the watchdog (`bin/lead-watch.sh`) and the answer parsing look for them in the text. In an English project — only these:

| Русский | English |
|---|---|
| `━━ СЛЕДУЮЩИЙ: блок N «…» · задание N.K · выдан` | `━━ NEXT: block N “…” · task N.K · issued` |
| `ПРОГОН rN НАЧАТ` · `ПРОГОН ПРОЙДЕН` · `СХЕМА НЕ ГОТОВА` | `RUN rN STARTED` · `RUN PASSED` · `SCHEME NOT READY` |
| `ОПИСАНИЕ ПРОГОНА` · `СХЕМА КРАТКО` | `RUN DESCRIPTION` · `SCHEME OUTLINE` |
| `СТОИТ` · `РОМБ — Jev не решил, реши сам` · `ШЛЮЗ` | `STUCK` · `DECISION — Jev did not decide, decide yourself` · `GATEWAY` |
| `ТИШИНА` · `ПРОГОН ЗАКРЫТ` · `НЕТ СТАТУСА` (сторож) | `SILENCE` · `RUN CLOSED` · `NO STATUS` |
| `задание в файле ПУТЬ` | `task in file PATH` |
| `Вход:` · `(прежний вход)` · `Круг 2 — вернул ромб …` | `Input:` · `(previous input)` · `Round 2 — decision … sent it back` |
| `Рабочая папка:` · `Ответь одной строкой вида:` | `Work folder:` · `Answer in one line like:` |
| `ОТВЕТ worker: 137.3: …` · `ОШИБКА: задание 137.3 — …` · `Замечание: … — 76.4: …` | `WORKER ANSWER: 137.3: …` · `ERROR: task 137.3 — …` · `Note: … — 76.4: …` |
| статус `прогон rN · running · принято шагов: 3 · сейчас: …` | `run rN · running · accepted steps: 3 · now: …` |
| `ok: блок 137 принят · задание 137.3` · `ромб 138 → нет` | `ok: block 137 accepted · task 137.3` · `decision 138 → no` |
| образец `a=<число> <слово> <файл> <текст>` · `вызовов=<число>` | `a=<number> <word> <file> <text>` · `calls=<number>` |
| условие ромба `содержит` · `начинается` · `кончается` | `contains` · `starts with` · `ends with` |

The parser understands both languages (patterns, conditions, `calls=`, `WORKER ANSWER:`, `→ yes/no`). The names `.попытки/` and
`схема.txt` are not translated — they are paths. The reference for the words is `lang/en/agents.json` (`agents.go.*`); check against it.

## Documentation in English

`en/content.json` holds the same articles with the same `slug`, `parent`, `order`, `references`, `resource_type`,
`status`; what gets translated is `title`, `summary_html`, `body_html`, `tags`, `source_note`. Links `[[slug|text]]`
and `[[number|text]]` — do not touch the address, translate only the text. Code inside `<code>`/`<pre>` stays as is.
Publishing: `php md_backend/документация/publish.php --lang=en`. The reading page shows the person's
language; if there is no English version, it shows the Russian one.

## Checking

```sh
PHP=/Applications/XAMPP/xamppfiles/bin/php
$PHP tests/v2/check-i18n.php --part=editor --left   # dictionaries, keys in code, what is still in Russian
node --check public/src/…/файл.js                    # every changed JS file
$PHP -l lib/…/файл.php                               # every changed PHP file
curl -s -b goblin_lang=en http://localhost/goblin/index.php | head   # the page builds in English
```

`check-i18n.php` fails on ru/en key mismatches, foreign substitutions and keys that are missing from the dictionary;
the "still in Russian" lines are a guide: some of them rightly stay (data, regular expressions,
phase-two texts).
