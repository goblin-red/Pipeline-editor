# Врезки документации

Врезки доступны у любой статьи и хранятся отдельно в `documentation_callouts`.

- `future_plan` — «План на будущее», золотистый фон. Автоматически выводится также в `?page=future-list`, со ссылкой на исходную статью и якорь врезки.
- `agent_correction` — «Исправления агента», сиреневый фон. Дополнение ИИ-агента к исходной статье, не автоматическое утверждение нового требования.

Пустые блоки не показываются. Редакторы статей и повторная публикация основных текстов не удаляют врезки. В JSON-представлении документации они передаются отдельным массивом `callouts`. Поиск учитывает их текст в исходной статье.

## Добавление и изменение агентом

Подготовить HTML-файл с содержимым, обычно два коротких абзаца. Затем выполнить:

```sh
/Applications/XAMPP/xamppfiles/bin/php md_backend/документация/save-callout.php --page=frontend --key=my-idea --kind=future_plan --file=/absolute/path/idea.html --author=Codex
```

Для уточнения агента использовать `--kind=agent_correction`. Необязательный `--order=10` задаёт порядок. Пара `page + key` постоянна: повторный запуск обновляет ту же врезку с сохранением ID. Разные ключи создают отдельные врезки.

HTML — доверенный авторский материал, как и основной текст документации. Внутренние ссылки используют `[[ID|подпись]]`, где ID — запись `documentation_links`, принадлежащая исходной статье. Форма `[[slug|подпись]]` также поддерживается: CLI сохраняет связь и заменяет slug её ID. Примеры внутри code/pre не преобразуются.

Связь статьи с общей подборкой сохраняется в `documentation_links` в обоих направлениях. Сам текст плана не копируется. Автор — явная подпись, а не средство удостоверения личности.

## Примеры

Оба демонстрационных блока находятся в статье `frontend`. Их ключи: `example-future-plan`, `example-agent-correction`. Это примеры оформления, а не утверждение реализованных возможностей.

`install-callouts.php` применяет миграции документации, публикует единый content.json и создаёт примеры только при их отсутствии. Для обычных правок использовать save-callout.php.

## Утверждение

Новая врезка получает approval=pending. Явное решение пользователя записывается отдельно:

```sh
/Applications/XAMPP/xamppfiles/bin/php md_backend/документация/review-callout.php --id=123 --decision=approved --by='Имя пользователя'
```

Значения: pending, approved, rejected. Агент не утверждает свою врезку без решения пользователя. При изменении текста, типа или автора прежнее решение сбрасывается. Перемещение врезки по порядку решение сохраняет. Утверждение не переносит текст в основную статью автоматически.

## Удаление

```sh
/Applications/XAMPP/xamppfiles/bin/php md_backend/документация/delete-callout.php --id=123
```

После удаления или смены типа граф пересобирается. Связь с подборкой остаётся, если её использует другая плановая врезка или сама статья. Подборка не хранит копий текста. Врезка в самой рубрике future-list выводится один раз.
